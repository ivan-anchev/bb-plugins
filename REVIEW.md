# Review rules

Findings that came up repeatedly in review here and were fixed every time. Flag them on sight.

## Always flag

- Refresh or retry paths that leave a failed read in place: Refresh and reselection must re-read failed or cached-failed results (use the SDK query's refetch), and errors must show next to any data still displayed.
- Casts or JSON round-trips that hide a test fixture's type, such as a fake SDK or a fake row. Type the fake against what the code uses and build valid rows. The one exception: a deliberately off-type row that stands in for data from a newer host, with a comment saying why.
- A switch over a union without a compile-time exhaustiveness check. When the union is host data, the runtime fallback must return something neutral, not throw, because the host can send variants newer than the plugin's SDK.
- Async work that outlives its owner, or one shared timer or clock that lets one reader starve another. Commit cursors only after the read succeeds, clear timers and abort pulls in stop(), and treat a status-only change as a change.
- File paths trimmed, sanitized, or partly decoded on the way from the diff (stripped zero-width or bidi characters, `.trim()`, a dropped trailing space or BOM, octal escapes decoded before header parsing), which silently moves a hunk to another file: a path must keep exact byte identity from the diff parser through prompts, schemas, validation, and storage. Escape it for display; never normalize it.
- Small status text in a theme colour that fails WCAG AA contrast, especially on a raised surface such as a grey `bg-muted` card (`text-destructive` is 3.46:1 in dark; `text-destructive-text` passes on the page at 5.09:1 but drops to 4.00:1 on `bg-muted`): measure text contrast against the surface the text actually sits on, in both themes, and reach 4.5:1 by using the theme's text-specific token (such as `text-destructive-text`) and, on raised surfaces, a colour that passes there.
- A background job (sweep, timer) that acts on state it read before its awaits: re-read the state right before any irreversible action (suspend, stop, delete), check the abort signal after every await and stop applying actions once the time budget aborts, and keep protective work such as a lease renewal going until the risky action is confirmed done.
- A safety scan (secrets, credentials, identities) that passes a location it could not fully inspect, whether an unreadable file or folder, a hidden file, a name with spaces, a symlinked folder, or a verdict from the filename instead of the content: fail closed, so walk every entry exactly as named (including hidden files, and following symlinks), judge by content, and refuse on any inspection error.
- Component state seeded from props at mount for data a refresh can change (resolved state, comment counts, folds): derive it from the current read, and keep only the reader's own choices in state.
- A time window ("the last 7 days") built on GitHub search date qualifiers (`closed:`, `merged:`, `updated:`) with no exact timestamp cut in code: the qualifiers take a date, not a time, so the window runs up to a day long, and `closed:` silently drops some PRs, such as a closed draft. Search wide (such as `updated:>=` a day before the window opens), then keep only results whose `closedAt`/`mergedAt` falls inside the window.
- A gh refusal shown in words its output doesn't establish, as when a merged PR is called closed because gh prints the same line for both, or gh's raw transport text (`unexpected EOF`) shows instead of the plugin's connection message: claim only the state the output proves (read the PR's state, or word the refusal neutrally when the output can't tell), and map every transport failure, not just the ones a test produced, to the connection message.
- An export that no production code imports, as when a constant, type, or helper is exported only so a test can reach it (or is imported by nothing at all): keep it private and test through the module's public surface (assert the wording in the output, not by importing the constant), or move the logic to the layer that has a real production consumer.
- A change that grows a source folder past about nine files, as when a new component or reader lands beside eight others in `src/ui` or `src/data`: group the closely coupled files, tests included, into a feature subfolder (such as `ui/row/` or `data/pull-request/`), update the imports, and add no forwarding wrappers or re-exports at the old paths.
- A "last written" marker that skips repeat saves but no longer matches storage, as when it advances before a quota failure so the same state is never retried, or a save that reaches `sessionStorage` but fails in `localStorage` leaves it stale so saving the earlier state again is skipped and reload restores the failed one: advance the marker only after every store's write succeeds, clear it on any failed write, and test a failed write followed by a retry.
- Persisted or host data checked only partly at the parse boundary, as when `JSON.parse` of malformed storage throws before the schema check runs, or the schema accepts duplicate ids that later code assumes are unique (closing one tab then removes both): treat a decode failure like invalid data, and enforce every invariant the code relies on (unique ids, references that resolve) in the parser, repairing what can be repaired and dropping the rest.
- An elapsed-time window or an untested assumption standing in for a host event, as when composer focus is corrected "for 1 s after show" or "a composer's first focus is bb's autofocus": end on the event the code can observe (each composer's readiness), and where only timing can tell the host's action from the user's, measure it live over many runs and on a slowed CPU, base the rule on the measured result (such as "the first frame after mount"), keep any timer only as a backstop, and note in a comment what to re-measure when the host changes.
- A tool or event handler that decides on facts it read before an await and then writes, starts, stops or announces something, as when two `agent_start` calls on one issue both pass the "no agent holds it" check, or a handoff stores its report and starts a verifier after its agent was stopped mid-call: run every operation that reads and changes one entity's facts through one serial path for that entity, including writes that have no effect in the host, read the facts only once the operation holds that path, and decide and write in one store transaction where the store allows it.
- A test double kinder than the host it stands in for, so a test passes where the host would fail, as when a fake thread list hands out its live objects where bb returns copies, a fake turn goes straight to active with no `starting` phase, a fake keeps answering for a deleted thread that bb answers with a 404, or a test asserts an order that only the fake's promise scheduling guarantees: make the fake as strict as the host in every behaviour the code depends on (copies, lifecycle phases, errors for things that are gone, an environment only where one was made), and assert no order the host doesn't promise.
- A rule that holds only if every caller remembers one more step, as when every effect after a lease must call `check()` first, or every write that can move a status must also tell a change counter (each of three review rounds found one more writer that didn't): make it structural so no caller can skip it, such as holding the turn until its calls settle instead of a lease with checks, or having the store count its own writes as they commit.
- A fact that has one home derived a second time somewhere else, as when catch-up states a parent's status from its final check's outcome instead of from the status reader, the PR watch and the issue reader each pick "the issue's agent" by a different rule, inherited blockers are inferred by subtracting two reads taken at different moments, or one announcement is made from every place that might cause it: read the fact from its one home, take values that must agree from one read, and make each announcement in one place.
- Text in a tool result, a refusal, an agent's first message or a guide that claims what the code doesn't do or can't know, as when a result says a new agent "has" commits before bb has cut its branch, a refusal's way forward is a move the rules forbid, or a stop whose answer was lost is reported as "wasn't stopped": say only what the code has established, word the uncertain case as uncertain, and test that each refusal's suggested recovery works when followed.
- Memory of what the code observed, announced or started that is written or deleted at a different moment than the thing it describes, as when a remembered "the manager was told this dependency closed" outlives its relation and is lent to the same relation added again, a verifier's thread id is overwritten when its check is superseded so its failed stop is forgotten, or a saved PR snapshot stands in for a fresh read as proof of a push: store the memory on the row it describes, written and deleted in that row's transaction, or ask the source of truth each time.
- A store operation that makes several writes, or a file write and a store write, with no test that fails one of them, as when a handoff saves its report file and then its row, or an announcement records several rows in one transaction: make one write fail, show that every other write was undone (only the operation's own file write, never a person's edit), and show that a retry then succeeds.
- A payload that carries fields its consumer never reads, or a payload test that would still pass with a field dropped, nulled or added, as when the board's RPC sends a verdict's CI result the board never shows, or sending `parentId: null` on every row passes every test: send only what the consumer reads, and assert the exact keys and values through the real RPC.
- A replacement or stop that takes back only part of what the plugin set going for the thing it replaces, as when a handover withdraws the plugin's queued messages from the current agent's thread but not an ended agent's, withdraws the manager's messages but not a reminder sent with no sender, or stops a thread only when bb reports it running, so a background command wakes it later: list everything the plugin queues or starts for that thing, from every sender, take all of it back, confirm by reading again, and refuse to continue while anything is left.
- A status or failure line that leads with a summary its reason contradicts, as when "Failed verification: 1 of 1 criteria passed" gives the reason (the commit wasn't on a clean tree, or CI failed) only in the next sentence, or an issue whose agent was stopped reads "Not started": lead with the reason.

## Never flag

- Small ids, kinds, counts and times in the theme's `--subtle-foreground` below 4.5:1 contrast, where the row copies Activity Sidebar's, which uses the same token for the same things: the Always flag rule on status text still applies to text a reader acts on, such as a headline, a Needs you reason or a result.
- Behaviour the plugin doesn't own, as when a person types into a thread the plugin stopped and wakes it, or a host call never answers: it is a stated limit for the PR, not a finding.
