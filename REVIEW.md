# Review rules

Findings that came up repeatedly in review here and were fixed every time. Flag them on sight.

## Always flag

- Refresh or retry paths that leave a failed read in place: Refresh and reselection must re-read failed or cached-failed results (use the SDK query's refetch), and errors must show next to any data still displayed.
- Hover- or focus-revealed popups (tooltips, hover cards) that break dismiss, hover, or focus rules: Escape must close them wherever focus is, they must stay open while hovered or while the trigger has focus, and the pointer must reach them with no dead gap between trigger and popup (WCAG 1.4.13).
- Casts or JSON round-trips that hide a test fixture's type, such as a fake SDK or a fake row. Type the fake against what the code uses and build valid rows. The one exception: a deliberately off-type row that stands in for data from a newer host, with a comment saying why.
- A switch over a union without a compile-time exhaustiveness check. When the union is host data, the runtime fallback must return something neutral, not throw, because the host can send variants newer than the plugin's SDK.
- Async work that outlives its owner, or one shared timer or clock that lets one reader starve another. Commit cursors only after the read succeeds, clear timers and abort pulls in stop(), and treat a status-only change as a change.
- File paths trimmed, sanitized, or partly decoded on the way from the diff (stripped zero-width or bidi characters, `.trim()`, a dropped trailing space or BOM, octal escapes decoded before header parsing), which silently moves a hunk to another file: a path must keep exact byte identity from the diff parser through prompts, schemas, validation, and storage. Escape it for display; never normalize it.
- Focus dropped to the page body when the focused control unmounts or remounts, as on a screen transition or a header that remounts when state changes: move focus to a deliberate target, such as the new heading or the replacement control, and keep stable chrome (headers, toolbars) mounted across states.
- Small status text in a theme colour that fails WCAG AA contrast, especially on a raised surface such as a grey `bg-muted` card (`text-destructive` is 3.46:1 in dark; `text-destructive-text` passes on the page at 5.09:1 but drops to 4.00:1 on `bg-muted`): measure text contrast against the surface the text actually sits on, in both themes, and reach 4.5:1 by using the theme's text-specific token (such as `text-destructive-text`) and, on raised surfaces, a colour that passes there.
- A scrollable or text-only content area (a tab panel, a page region) that the keyboard cannot reach or scroll, as when it has no tab stop, the tab stop sits on an outer wrapper while an inner container scrolls, or the tab stop appears only once content loads: give it exactly one `tabIndex={0}`, on the element that actually scrolls (browsers keyboard-scroll only the focused element and its ancestors), in every state, loading and error included.
- A background job (sweep, timer) that acts on state it read before its awaits: re-read the state right before any irreversible action (suspend, stop, delete), check the abort signal after every await and stop applying actions once the time budget aborts, and keep protective work such as a lease renewal going until the risky action is confirmed done.
- A safety scan (secrets, credentials, identities) that passes a location it could not fully inspect, whether an unreadable file or folder, a hidden file, a name with spaces, a symlinked folder, or a verdict from the filename instead of the content: fail closed, so walk every entry exactly as named (including hidden files, and following symlinks), judge by content, and refuse on any inspection error.
- Esc paths that lose an open draft or selection, as when Esc pressed on the page body after a click outside a comment box reaches bb's global handler and leaves the page, or Esc is handled only on a box's textarea: while a box or selection is open, hold bb's Esc wherever focus is (prevent its default in a bubbling keydown listener on the document, so menus inside still close on Esc first), and handle the box's own Esc on its container so an empty box closes from any of its controls.
- Component state seeded from props at mount for data a refresh can change (resolved state, comment counts, folds): derive it from the current read, and keep only the reader's own choices in state.
