Experimental: it may break with a bb update.

boat Sandbox gives bb threads their own cloud computer on boat.dev. A sandbox starts when a thread needs one, stops after it has been idle, and resumes later on the same disk, so the work on it is still there. You pick what each one starts from: a template (a boat saved snapshot you made, with your tools already installed) and a boat environment (which decides the sign-ins, GitHub token and secrets it gets). A card on the New thread screen shows what boat has cost you lately, the sandboxes running now, and the money left. From a thread's side panel you can watch its sandbox's desktop live, view only.

## What you need

- A boat.dev account on a personal wallet, with zero data retention off.
- A boat API key made with `boat api-key create bb --preset ci`.
- A Git remote on the bb project, which the sandbox clones.
- A bb server reachable from the internet (bb Connect), so the sandbox can connect back to it.

## What you get

- **boat Sandbox in the new-thread environment picker.** A thread started there gets a new boat sandbox with the project cloned and `.bb-env-setup.sh` run, and the sandbox is deleted when bb removes the machine. A chip in the composer shows the template, environment and size it will use, and lets you pick each from what boat has before you send. From the CLI: `bb thread spawn --environment-provider boat-sandbox --machine-inputs '{"template":"node-tools","environment":"base","preset":"large"}' --prompt "…"`.
- **A boat icon on sidebar thread rows** for every thread that runs on a boat sandbox, except a child thread on the same sandbox as its parent, whose parent's row already shows it. It sits on the row's metadata line, which bb shows while its thread row metadata experiment is on and Organize → Rows → Metadata is turned on. A setting turns it off.
- **A boat spend card on the New thread screen**, in its own row under the other homepage cards. It charts the last 30 days of boat machine time a bar a day, with the 30-day total; lists the boats this bb server is running now as Activity-sidebar rows with each one's size and cost this month, ticking every second, and what they cost an hour together; and shows the money left (plan time left plus the wallet) and when the plan renews. A wallet that owes money gets a warning with a link to boat's billing page. boat keeps no daily history, so the plugin records its month-to-date meter every few minutes from install on: days before that are blank until **Backfill 30 days** fills them with boat's own daily machine time, read from an undocumented boat route that needs a key with the `account.admin` scope.
- **A Computer card and page for every boat thread.** The thread's Info tab shows a Computer card with a drawing of a desktop, and the New tab's Actions list a Computer row. Either opens the Computer page, a side-panel tab with the sandbox's desktop live (boat's noVNC view), scaled to the panel and view only: clicks, keys and scrolling on it never reach the sandbox. The first look after a sandbox starts takes about half a minute while boat starts the view; later ones take seconds. A stopped or starting sandbox gets one plain line instead, and the page comes back to the live desktop by itself after a resume. Threads on any other machine show neither.
- **A boat Sandbox section in Settings** for your boat API key, how long a sandbox may sit idle before it stops (15 minutes by default), the default sandbox size, the default template, the default environment, and whether sidebar rows show the boat icon.
- **`bb boat status`**, which checks the key and shows the boat account, the wallet it bills, whether zero data retention is on, how many sandbox starts are left in each window, what a thread gets by default, and whether Claude Code and Codex sign in there and the AI proxy is on, and which GitHub login threads use. Anything missing comes with the one step that fixes it.
- **Templates and environments from boat.** Save any boat sandbox with `boat snapshot <sandbox-id> <name>`; `bb boat templates` lists every saved snapshot and every boat environment, with what each environment passes and the exact `--machine-inputs` to use it. An unknown name is refused before the thread starts. A template saved from a bb thread sandbox works too: on create, the plugin removes the old machine's bb identity before bb enrolls the new one.
- **`bb boat sandboxes`**, which lists this server's sandboxes with their bb machines and notes anything out of step, such as a sandbox boat stopped by itself or one no machine uses.

## How it works

The plugin talks to boat's REST API with a key you make with `boat api-key create bb --preset ci`. bb stores the key as a secret file and never shows it again. Claude Code and Codex sign in with what the chosen boat environment passes; the plugin writes no credentials itself, and checks on every create that boat attached the environment it asked for. GitHub uses bb's forwarded login whenever bb forwards one, otherwise the environment's boat token over HTTPS, so a project with an SSH remote (`git@github.com:…`) still clones and pushes. The plugin refuses accounts with zero data retention, because a stop there deletes the sandbox, and keys that bill an organization wallet.

bb's enrollment secret travels to the sandbox as a file in a private directory, never as command text, so it never appears in boat's 90-day command history. Each sandbox carries labels that tie it to this bb server and thread, so an interrupted create picks up its sandbox instead of starting a second one.

Once a minute the plugin stops a sandbox whose threads have been idle for the set time; a thread running a long command is never idle. A follow-up to the thread resumes the same sandbox in seconds, with its files where they were. While bb runs, the plugin keeps pushing boat's auto-stop deadline back, so boat never stops a sandbox bb is using. The same check puts bb right when boat and bb disagree: a sandbox boat stopped is recorded as suspended so a follow-up resumes it, a suspended sandbox someone resumed by hand is stopped again, and a sandbox no machine uses is stopped after 15 minutes but never deleted.

The Computer page asks boat for the sandbox's noVNC page each time it opens and again every few seconds while it shows, but never wakes, stops or extends a sandbox, and watching is not thread activity, so it does not hold off an idle stop. boat charges nothing extra for the view. The plugin never asks for a public desktop URL. View only is noVNC's own `view_only` setting, and the page also makes the frame inert, so nothing typed or clicked there reaches the sandbox. boat enforces view only in its page, not on the sandbox, so the desktop URL would allow control if opened on its own; the page never shows it as text or a link. The API key never leaves the bb server.
